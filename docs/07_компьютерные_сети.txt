Лекция 7. Компьютерные сети: модель OSI, TCP/IP, маршрутизация, безопасность

Кафедра информационных технологий

=== 1. Что такое компьютерная сеть ===

Компьютерная сеть — это совокупность соединённых между собой вычислительных устройств, обменивающихся данными по общим правилам (протоколам).

Классификация по масштабу:
- PAN (Personal Area Network) — персональная (Bluetooth, USB).
- LAN (Local Area Network) — локальная, в пределах здания или кампуса.
- MAN (Metropolitan Area Network) — городского масштаба.
- WAN (Wide Area Network) — глобальная, включая Интернет.

=== 2. Модель OSI ===

Модель OSI (Open Systems Interconnection) описывает взаимодействие в сети на семи уровнях. Каждый уровень решает свою задачу и общается только с соседними уровнями.

1. Физический — передача битов по каналу (кабель, радио).
2. Канальный — кадры, MAC-адреса, обнаружение ошибок (Ethernet, Wi-Fi).
3. Сетевой — маршрутизация пакетов между сетями, IP-адреса (IP, ICMP).
4. Транспортный — надёжность, порядок, потоки (TCP, UDP).
5. Сеансовый — установка и завершение сеансов связи.
6. Представления — кодирование, шифрование, сжатие.
7. Прикладной — протоколы приложений (HTTP, SMTP, DNS, FTP).

Модель OSI — эталон для понимания. На практике чаще используют более простую четырёхуровневую модель TCP/IP: канальный, сетевой, транспортный, прикладной.

=== 3. TCP и UDP ===

TCP (Transmission Control Protocol):
- Устанавливает соединение (three-way handshake: SYN → SYN-ACK → ACK).
- Гарантирует доставку и порядок пакетов.
- Управляет потоком и перегрузкой.
- Используется там, где важна надёжность: HTTP, HTTPS, SMTP, SSH, базы данных.

UDP (User Datagram Protocol):
- Без соединения, без гарантии доставки.
- Минимальные накладные расходы, низкая задержка.
- Используется там, где важна скорость и допустимы потери: видеосвязь, онлайн-игры, DNS-запросы, стриминг.

=== 4. IP-адресация и маршрутизация ===

IP-адрес — числовой идентификатор устройства в сети.
- IPv4: 32 бита, записывается как 4 октета (192.168.1.1). Всего ~4,3 млрд адресов.
- IPv6: 128 бит, записывается в шестнадцатеричном виде (2001:0db8:85a3::8a2e:0370:7334). Огромное адресное пространство.

Маска подсети определяет, какая часть адреса относится к сети, а какая — к хосту.

Маршрутизация — процесс выбора пути для пакета от отправителя к получателю. Маршрутизатор (router) хранит таблицу маршрутизации и на каждом шаге пересылает пакет ближе к цели.

Протоколы маршрутизации: RIP, OSPF (внутри автономной системы), BGP (между провайдерами).

=== 5. HTTP и HTTPS ===

HTTP (HyperText Transfer Protocol) — протокол прикладного уровня для обмена документами. Работает поверх TCP, порт 80.

Запрос HTTP состоит из:
- Метода (GET, POST, PUT, DELETE, PATCH).
- URL и версии протокола.
- Заголовков (Host, User-Agent, Content-Type, Authorization).
- Тела (для POST/PUT/PATCH).

Ответ содержит код состояния (200 OK, 404 Not Found, 500 Internal Server Error), заголовки и тело.

HTTPS — HTTP поверх TLS. Обеспечивает:
- Шифрование данных (никто в сети не прочитает содержимое).
- Аутентификацию сервера через сертификат.
- Целостность передаваемых данных.
Порт по умолчанию — 443.

=== 6. DNS ===

DNS (Domain Name System) — распределённая система, которая переводит доменные имена (example.com) в IP-адреса (93.184.216.34).

Процесс разрешения имени:
1. Клиент спрашивает у локального рекурсивного резолвера.
2. Резолвер идёт к корневым серверам, затем к серверам TLD (.com, .ru), затем к авторитетному серверу домена.
3. Ответ кэшируется на всех уровнях.

Основные типы DNS-записей: A (IPv4), AAAA (IPv6), CNAME (алиас), MX (почтовый сервер), TXT (произвольный текст, часто для верификации), NS (сервер имён).

=== 7. Безопасность в сетях ===

Основные угрозы:
- Перехват трафика (sniffing).
- Атака посредника (man-in-the-middle).
- Отказ в обслуживании (DDoS).
- Подмена DNS.
- Фишинг.

Средства защиты:
- Шифрование (TLS, VPN).
- Аутентификация (пароли, ключи, MFA).
- Межсетевые экраны (firewall), фильтрация трафика.
- Системы обнаружения вторжений (IDS/IPS).
- Регулярное обновление ПО и мониторинг.
